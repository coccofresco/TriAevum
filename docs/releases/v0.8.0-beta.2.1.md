## A corrected beta.2

> [!WARNING]
> **Still a beta.** If something breaks (or works), please
> [open an issue](https://github.com/coccofresco/TriAevum/issues/new) with your
> GPU, driver version, operating system, the console output and
> `oot3d_native_game.log` (in the `data\logs` folder of your installation),
> plus what you were doing right before it went wrong.

Beta.2.1 is beta.2 with the fixes found while preparing the next releases.
Windows and Linux, as usual. The game, its settings and your saves work as in
beta.2.

### Fixed

- **Video memory filling up while the game was held**: with the in-game menu
  open in scenes that copy the screen into textures, every displayed frame kept
  a new copy alive until the video memory ran out and the game stopped. Held
  frames no longer keep their copies; the memory stays flat however long the
  menu stays open.
- **Windows: the game could not start after installation** on a clean system:
  when Forge placed the game at the root of the installation it also removed
  the C++ runtime DLLs the game loads from there. They stay beside it now, and
  the release check verifies every DLL the game needs is where Windows looks
  for it.
- **The first launch no longer waits for minutes**: Forge's GPU pipeline
  preparation now runs through the game executable itself, after installation,
  so the graphics driver keeps the prepared pipelines for the game you start.
  The first launch after installing starts in seconds instead of preparing
  the renderer again.
- **Linux AppImage**: every start used to prepare the renderer again, because
  the AppImage runs from a new location each time. The game now runs from a
  stable copy in its data folder, refreshed when you replace the AppImage, so
  later starts are as quick as the first.
- **Linux bundles are signed**: the AppImage and the Flatpak now carry the
  publisher's signature of their package, as the Windows package already did.

### Known issues

- #105: the courtyard crawl hole issue could not be reproduced; it stays a
  known issue.
- #96: objects can flicker at interpolated 60 FPS with native lighting; not
  fixed in this release.

### Updating

Back up your saves first; it is still a beta.

- **Windows**: in Forge, choose Update and pick the beta.2.1 ZIP, or extract
  the ZIP to a new folder and run `TriAevumForge.exe`. The first start after
  updating prepares the game once more.
- **Linux**: replace the AppImage, or install the new Flatpak bundle with the
  same `flatpak install --user` command; saves stay where they are.

Use your own decrypted EUR/USA `.3ds` or `.cci` dump (original or Rev 1);
Japanese, Korean and Taiwanese releases are not supported yet. The previous
notes: [beta.2](v0.8.0-beta.2.md), [beta.1.2](v0.8.0-beta.1.2.md).
