# Beta.1.1 Release Qualification

Date: 2026-10-18. Scope: Windows x64 portable ZIP, Linux x86-64 AppImage and
Linux x86-64 Flatpak bundle (candidate b11d). Supported inputs: decrypted EUR
and USA dumps, original and Rev 1, as for [beta.1](v0.8.0-beta.1-qualification.md).

## Source and Package Boundaries

- Runtime/source freeze: `b20ff67e19716319c518665b31931556f4711653`
  (branch `release/0.8.0-beta.1.1`). The release tag also includes the
  subsequent documentation-only records (release notes and this file).
- All packages pass the allowlist/hash/source audit with no errors. Windows
  contains 88 catalogued files; Linux contains 579. The AppImage and the
  Flatpak carry the same audited Linux inventory.
- New package content: the two SingleScreen 3.0 files TriAevum needs
  (`resources/topscreen/singlescreen-3.0/custom_ui01.ctxb` and
  `zelda_link_ext.zar`, role `topscreen_singlescreen_asset`), unchanged from
  the official archive and shipped with the author's permission
  (`LICENSES/SingleScreen-3.0.md`). The audit accepts them only at those paths
  with those hashes. The archive itself, its IPS patch, ARM payload, HD atlas
  and HD fonts are not distributed; Forge imports the HD graphics only from an
  archive the user provides.
- Runtime and Forge are packaged separately from ROM-derived data. No ROM,
  `code.bin`, save, capture or SDK is distributed.
- Precompiled title module, DLSS module and MXAO library are byte-identical to
  beta.1b and beta.1c: title Windows `91f18fc498fa8a3a…`, Linux `122d99685e9ba013…`;
  DLSS Windows `8ec337a5…`, Linux `84dcc345…`; MXAO Windows `ee7f04b6…`,
  Linux `64b10155…`.

## Enhanced Shader Corpus

The corpus is regenerated from recorded variant requests, not from shader text
(issue #76), and qualified by three release gates.

- Recording at the release runtime (`b20ff67`), split across two machines:
  the Better-scene sweep (419 visits, 399 arrived; the 20 failures are the adult
  Castle Town Entrance, Market and Hyrule Castle warps, which fail in every
  sweep) under the product and the maintainer's graphics profiles, Windows for
  scenes 0-14 and the Linux reference machine (developer build of the same
  commit) for scenes 15-48, plus a second Linux pass of scenes 15-48; then event
  sessions on Windows (Barinade under both profiles, Kokiri storms under both,
  a game over, a cutscene) and the boot to the file select under both.
- Linux recordings replay on Windows with no witness mismatch, record the same
  effective graphics effects as the Windows sweep, and their runtime inputs
  match the release checkout (only platform files differ between the two
  builds).
- Regeneration: 14 sessions, 133,876 requests, 0 witness mismatches, 0 resolve
  failures; 1,813 modules (152.2 MB), pack SHA-256 `29fde8ddee7ef971…`,
  1,334 runtime pipeline recipes; closure 0 missing modules, 0 missing recipe
  modules (gate 2).
- Gate 1 (freshness): `qualified` against the release checkout, generator and
  per-session runtime inputs.
- Gate 3 (developer launch, empty renderer cache, no recorders): Barinade
  fight, Kokiri storms and boot to the file select, each under both profiles:
  0 shaderc calls, 0 PICA pack misses, 0 pass-artifact misses, exit 0.

## Checks Performed

- Release tooling: 524 tests, 14 explicitly skipped, no failures.
- Renderer change since the previous candidate (`b20ff67`): water-only Hi-Z
  reflection rejection. Tests `pica_water_map_tests`, `hiz_water_view_tests`
  and `oot3d_graphics_foundation_tests` pass; the built-in pass pack is
  regenerated and checked; the 7-run TopScreen smoke set is unchanged. With
  water reflections off, captures are bit-identical; with them on, they differ
  only at water pixels whose wave phase follows the wall clock, which differ
  equally between two runs of the unchanged shader.
  `reflection_weight_gpu_tests` fails before and after this change (its fixture
  binds no water uniform). Developer launch, product Enhanced settings,
  3840x2160, no upscaler, RTX 3060: Kokiri Forest 27.1 -> 18.0 ms per frame,
  opening scenes 19.1 -> 18.6 ms.

## Known Limits

- AMD Radeon pipeline preparation (#78, #84): the crash path through NRI's
  `DebugBreak()` is removed, but no AMD GPU was available; the access violation
  inside `amdvlk64.dll` reported later in #84 is not reproduced.
- Intel Arc on Mesa anv (#72): undefined-behaviour hardening only; the noise
  with pipeline libraries off is not confirmed fixed.
- #85 ("Cannot query the playable runtime"): cause unknown; Forge now records
  the runtime's output for the report.
- Pipeline recipes depend on when the runtime adopts an Enhanced pipeline, so a
  recording can miss a few; one recipe of the beta.1c corpus (a native,
  non-instrumented pipeline) is not in this one. Its modules are in the pack: a
  missing recipe means the pipeline is created in game, never a shader compile.
- Otherwise as beta.1b.
