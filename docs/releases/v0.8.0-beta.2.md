## Echoes of Time gets its name, in place

> [!WARNING]
> **Still a beta.** If something breaks (or works), please
> [open an issue](https://github.com/coccofresco/TriAevum/issues/new) with your
> GPU, driver version, operating system, the console output and
> `oot3d_native_game.log` (now in the `data\logs` folder of your installation;
> beta.1.2 kept it in `logs` next to the game), plus what you were doing right
> before it went wrong.

### The game has a name now

- **`TriAevum.exe` is now `Echoes_of_Time.exe`.** Forge installs the game under
  the product name, names its launch profile after it
  (`Echoes_of_Time.launch.json`) and removes the old `TriAevum.exe` from the
  installation folder, so a shortcut to the old file stops working: point it at
  `Echoes_of_Time.exe` (or start the game from Forge). Forge itself keeps its
  name, `TriAevumForge.exe`.
- **Linux** installs the game binary as `Echoes_of_Time` too; the AppImage and
  the Flatpak start it for you as before.
- **Updating in place from beta.1.2 works.** Extract beta.2 anywhere and run its
  Forge against your old folder (`TriAevumForge.exe --update-target <old
  folder>`, see `docs/TRIAEVUM_UPDATE_SIGNING.md`). Your saves, save states,
  settings, texture packs and launch options stay as they are; the old
  `TriAevum.exe` is replaced by `Echoes_of_Time.exe`.
- **Your files have one home: the `data` folder.** Save states move to
  `data\savestates` and logs and crash reports to `data\logs`. Existing save
  states are migrated on the first start and load from the new place; earlier
  logs stay where they were. `docs/TRIAEVUM_USER_DATA.md` lists every folder.
- **Forge is built per game.** The Forge in this package prepares Ocarina of
  Time 3D only, and the update helper carries the game's own icon.
- **The first start is quick.** Forge prepares the GPU pipelines through the
  game itself after installing, so the graphics driver keeps them for the game
  you start: the first launch after installation starts in seconds instead of
  preparing the renderer again.
- **Windows: the C++ runtime travels with the game.** The game and Forge are
  built with LLVM for Windows; the runtime DLLs they need sit beside the game
  in the installation, and the release check verifies that every DLL the game
  loads is where Windows looks for it. Optional FidelityFX upscaling still uses
  the Visual C++ runtime when it is installed on the system.
- **Linux AppImage**: the game runs from a stable copy in its data folder,
  refreshed when you replace the AppImage, so every start reuses the prepared
  pipelines even though the AppImage itself runs from a new location each time.
- **Signed on every platform.** The Windows package and the Linux AppImage and
  Flatpak carry the publisher's signature of their package.

### Graphics

- **Anisotropic texture filtering**, 4x in the Enhanced preset: floors and
  walls at a grazing angle stay sharp instead of melting into the distance.
- **HD texture replacements get their own mip chain** (#122): distant HD
  textures no longer shimmer or fall back to the wrong size. Texture packs
  named the Azahar way with three fields or mixed case are accepted.
- **Lighting fixes**: outdoor rooms with fixed light settings keep their own
  light, and filter-blended draws (water surfaces among them) keep the game's
  own appearance.
- **Renderer and grass work**: leaner draw preparation, fewer allocations per
  frame, and grass selection on the GPU that tests only what is in view.
  Shared engine work for a second title also landed in the renderer; the
  release is checked against beta.1.2 so that Ocarina of Time 3D looks the same
  except where listed here.
- **AMD on Windows**: the driver gets robust pipelines and a device-loss report
  that names what failed.
- **The shader corpus is recorded again** for this release, so the shaders the
  game asks for are prepared by Forge at install time instead of during play.

### Menus, controls and diagnostics

- **The Esc / R3 menu is sized for any screen**, the game pauses behind it,
  and master volume and mute have one control. A mouse resting over the game
  no longer swallows keyboard and controller input in the menu's dialogs, and
  a settings write that fails is reported instead of claimed.
- **Controller rumble** on damage and other game events, on pads that have it.
  Rumble stops cleanly when the window loses focus or the pad changes hands.
- **Input device log**: the log lists the connected pads and the keyboard for
  support reports, without serial numbers or your user name.
- **A fatal error ends the game promptly** with its error dialog instead of
  hanging while shaders are still being prepared.
- **Video memory stays flat while the game is paused** behind the menu, also
  in scenes that copy the screen into textures, however long the menu stays
  open.
- **Button prompt glyphs follow your pad** in the menu footer and help card.
- **Settings inside a moved installation keep their paths** (#124).

### Known limits

- Windows x64 and Linux x86-64 (AppImage, Flatpak) only: macOS and VR are not
  part of this release.
- The first start of a fresh installation may still compile a few shaders that
  no recorded session reached; it costs a short background compilation, never
  a stall.
- #105: the courtyard crawl hole issue could not be reproduced; it stays a
  known issue.
- #96: objects can flicker at interpolated 60 FPS with native lighting; not
  fixed in this release.
- To be completed from the qualification at the final cut
  (`v0.8.0-beta.2-qualification.md`).
