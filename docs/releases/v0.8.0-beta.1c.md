# TriAevum v0.8.0-beta.1c

## Save States Found a Place to Live

A Linux hotfix for beta.1b. Windows players can stay on beta.1b: on Windows
this version changes nothing.

- **Save states work in the AppImage and the Flatpak** (#61). Pressing F5 (or
  F1 → Game → Save states → Save state) failed with "Save state failed: cannot
  create the folder (Read-only file system)": the default folder sat next to
  the game's executable, inside the read-only package. On Linux, save states
  now go beside your save data:
  - AppImage: `~/.local/share/TriAevum/data/savestates`
  - Flatpak: `~/.var/app/io.github.coccofresco.TriAevum/data/TriAevum/data/savestates`

  A folder you chose with **Browse...** in that tab is still used as before.
  On Windows, save states stay in the `savestates` folder next to
  `TriAevum.exe`.

> [!WARNING]
> **Still untested in the wild**, as beta.1b. If something breaks (or works),
> please [open an issue](https://github.com/coccofresco/TriAevum/issues/new)
> with your GPU, driver, operating system, the console output and
> `oot3d_native_game.log`.

**Updating:** back up your saves first; it is still a beta.

- Linux: replace the AppImage, or install the new Flatpak bundle with the same
  `flatpak install --user` command; saves stay where they are.
- Windows: nothing to do. If you install it anyway, extract the ZIP to a new
  folder, run `TriAevumForge.exe` and copy the `data\savedata` folder of your
  previous folder into the new one before starting the game.

Everything else is beta.1b:
[release notes](https://github.com/coccofresco/TriAevum/blob/main/docs/releases/v0.8.0-beta.1b.md).
Use your own decrypted EUR/USA `.3ds` or `.cci` dump (original or Rev 1);
Japanese, Korean and Taiwanese releases are not supported yet.
