# Beta.1 Release Qualification

Date: 2026-10-13. Scope: Windows x64 portable ZIP, Linux x86-64 AppImage and
Linux x86-64 Flatpak bundle.
Supported inputs: decrypted EUR and USA dumps, original and Rev 1. Japanese,
Korean and Taiwanese releases are not supported; see
[catalogue ROM inputs](../TRIAEVUM_CATALOGUE_ROM_INPUTS.md).

## Source and Package Boundaries

- Runtime/source freeze: `8cc0445657dfaf209d2d552b55751fd4c50a4dc2`
  (branch `release/0.8.0-beta.1`, 3,474 tracked files). The release tag may
  also include this subsequent documentation-only record.
- Both packages pass the allowlist/hash/source audit. Windows contains 79
  catalogued files; Linux contains 537, including frozen Forge resources.
  The AppImage and the Flatpak carry the same audited Linux inventory; the
  Flatpak staging (`flatpak_package.py`) re-audits its copy and adds only the
  launcher, portal file chooser and desktop entry. Flatpak OSTree commit
  `fd7e921d4d852b9e46d29ef035469dd8a1c00e6ea1a5c980bdd3e5b166c7f9e4`,
  Freedesktop Platform 25.08, runtime fetched from Flathub on installation.
- Runtime and Forge are packaged separately from ROM-derived data. No ROM,
  `code.bin`, save, capture, SDK or TopScreen payload is distributed.
- iMMERSE MXAO ships as a separate library under its own notice
  (`LICENSES/iMMERSE-*`), distributed by the author's permission for this
  project only; all further rights remain the author's.
- The release's room analysis is bundled as two content-keyed tables
  (`forge/precomputed/interior-sun.masks`, `forge/precomputed/scene-lights.json`),
  bound to all three catalogued titles. They hold derived masks and emitter
  descriptions keyed by room-file hashes, not game assets; Forge still reads
  the user's RomFS and falls back to analysing any room the tables do not name.
- Precompiled title module, translated at `69776a2`:
  Windows `14d3e979d3605c9e5af2966927e58cc708f0662d30d14fce3ba51aedd35d7969`,
  Linux platform rebuild from the same translated sources in the Steam Runtime 4
  SDK `89a0b6c8693b89106696c3bc48c21ab3c412bbbf3d578a743f09cc16026705a8`.
- MXAO library: Windows `97e708ecbbea61922b446e7cd9d1437771c8bf9960127c28813d2325492d4bef`,
  Linux `64b101551d6d4e30fc0b738fac210fb9be52fbd1b206839d5ca653e91101679e`.

## Checks Performed

- Release tooling: 470 tests, 21 explicitly skipped, no failures.
- Clean-Windows script (`qualify_clean_windows.ps1`) on the final ZIP's
  contents, frozen Forge install worker, empty driver shader cache and no
  legacy renderer cache, no SDK on PATH. Zero objects compiled in both runs.

  | Input | Forge install | Boot | Guest draws | First-launch benchmark |
  | --- | --- | --- | --- | --- |
  | EUR (private dump) | 198.6 s | 1,200 frames, exit 0 | 42,790 | 46.9 FPS |
  | USA Rev 1 (No-Intro 1259) | 204.1 s | 1,200 frames, exit 0 | 42,697 | 47.0 FPS |

  Pipeline preparation completes all 1,872 pipelines (1,833 catalogued recipes,
  39 startup parts) on 12 threads in 174 s on a GeForce RTX 3060, zero failures; it is now most of
  the installation time. The room tables cover 671 interior-sun rooms (16 use
  the bounded fallback) for both inputs. The first-launch benchmark includes
  the preparation screen; later launches reuse the device cache.
- Packaged Linux runtime on Wayland (KDE, GeForce RTX 4060): Forge install
  222.6 s with the same 671 table-covered rooms; two bounded boots of 1,800 frames each, 38,834 and 38,720 guest
  draws, exit zero, no pending draws, file-select capture written; 49.6 FPS
  (first launch) and 58.4 FPS (second).
  An earlier candidate measured below 20 FPS only because the display was in
  DPMS off: the compositor throttled presentation. That is not a package fault.
- Flatpak on the same machine, in an isolated user installation (private
  `HOME` and `FLATPAK_USER_DIR`; the existing proof installation untouched):
  `flatpak install --user` of the bundle fetched Platform 25.08 and the
  matching NVIDIA GL extension from Flathub (76 s). The sandboxed Forge
  install worker read the ROM through a read-only grant into the app's own
  XDG data area in 223.0 s (671 table-covered rooms); two bounded boots of
  1,800 frames, 38,758 guest draws each, exit zero, no pending draws,
  file-select capture written, 49.4 and 58.1 FPS on the RTX 4060.
- Flatpak update: the same `flatpak install --user` command replaces the
  published alpha.2c bundle (commit `3c713d31…`) in place. On a copy of an
  alpha.2c installation's data, the normal launcher (`flatpak run`, no
  arguments) recognised the old title, refreshed it to the beta.1 module
  (same module hash as a fresh installation) in 206 s and started the game,
  which was still running 60 s later. The save file was unchanged and the new
  launch profile uses the same save directory. The real portal file chooser
  and the Forge GUI were not driven interactively.
- Frame rate parity: on the r3 candidate (same runtime source), the installed
  package and the developer build both hold the 60 FPS cap under the same
  launch profile, with about 4.7 ms CPU per frame.
- Forge declines Japan (both revisions), Korea and Taiwan dumps at the
  `verify` stage within seconds, with no data left in the data root.
- Before this release, installation took about 17 minutes on Windows and
  50 minutes on the Linux reference machine.
- Captures show the title sequence (Windows, frame 600) and the file-select
  menu (Linux). These are functional checks, not pixel equivalence. The Forge
  GUI was not driven interactively for this candidate; the install worker it
  launches was.

## Known Limits

Global illumination is experimental and not offered. Simulation remains 30 Hz;
60/90 FPS modes interpolate visuals. Japanese, Korean and Taiwanese releases
are not supported. Android and macOS are not included. This release does not
certify a complete playthrough. The Flatpak still has no AppStream metadata,
and AppImage and Flatpak keep separate data folders (no migration between
them).
