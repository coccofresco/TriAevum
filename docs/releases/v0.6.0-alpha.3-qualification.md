# Alpha.3 Release Qualification

Date: 2026-09-18. Scope: Windows x64 portable ZIP and Linux x86-64 AppImage.
Steam Deck is a compatibility target, not a hardware-tested claim.

## Source and Package Boundaries

- Runtime/source freeze: `5d13fa797015cbb5d83053bc85efd150a6aae7e1`.
  The release tag may also include this subsequent documentation-only record.
- The official source exporter includes 3,595 tracked files. Independent,
  untracked AOT experiments are excluded, not deleted or incorporated.
- Both packages pass the allowlist/hash/source audit. Windows contains 63
  catalogued files; Linux contains 529, including frozen Forge resources.
- Current runtime and Forge are packaged separately from ROM-derived data.
  No ROM, save, capture, SDK or TopScreen payload is distributed. Forge acquires
  the pinned official TopScreen archive and prepares textures/fonts locally.
- The previously audited portable shader corpus/pipeline recipes remain bundled
  under the explicit release-contract exception. No driver cache is distributed.
- Windows title DLL SHA-256:
  `304dae27dde2d287f0d911efd2d66e194359ad9403f5bd9083b05fc16f5ffe6b`.
  Paired translated C++ files were checked against the generator manifest;
  corresponding build support is `0b30a6ef99706bd96f3dd090fa5ac8b33bef3cd1`,
  the recorded byte-identical rebuild baseline. No title rebuild was needed.
- Linux preserves its qualified movie-capable module, SHA-256
  `fbf5291cc268d5162c58162319e625bba56877b5700ef0d26c937535592b4b69`,
  and its existing paired translated/build-source archives. The current runtime
  source is additionally included. Linux runtime/Forge use the pinned Steam
  Runtime SDK path; AppImage tooling and runtime hashes are verified.

## Checks Performed

- Windows release tooling: 410 tests, 14 explicitly skipped, no failures.
  Renderer preparation contract: seven tests also pass on Linux.
- Frozen Windows Forge, actual GUI install from the private decrypted ROM:
  successful, about 32 seconds including official TopScreen acquisition.
  Widgets mapped, no clipping; launch button enabled after preparation.
- Frozen Linux Forge: actual GUI worker import successful, about 35 seconds.
  The SSH/KWin presentation probe remained iconic, so mapped-widget visibility
  is **not** qualified by that run. Installation success is recorded separately
  and is not presented as a passing visibility test.
- Both installations produce font coverage enabled from 480p, TopScreen launch
  configuration, and the existing native-30/interpolated-60 defaults.
- Release testing caught a preparation-report regression: embedded renderer
  artifacts bypass the disk cache and were omitted from hit totals. Commit
  `5d13fa7` counts these explicitly: 22 built-in hits, zero compilations,
  zero failures. No rendering behavior or cache validation was weakened.
- Windows device preparation completes all 588 catalogued pipeline recipes.
  This is not proof that every runtime shader/pipeline is already covered.
- Packaged Windows runtime: two bounded clean boots, 1,800 and 1,200 presented
  frames, 69,243 and 43,069 guest draws respectively; exit zero, framebuffer
  captures written, TopScreen active, no pending or duplicate draws.
- Packaged Linux runtime on Wayland: two bounded clean boots, 1,800 presented
  frames each, 70,145 and 70,391 guest draws; exit zero, framebuffer captures
  written, TopScreen active, no pending or duplicate draws.
- The final AppImage itself also mounts and launches the game through its
  normal `AppRun`/frozen Forge entry: a bounded 900-frame run exits zero.
  Only the private test installation's launch profile and matching receipt
  were temporarily configured for a bounded capture, then restored. An initial
  probe missing the updated receipt was correctly rejected, not a game crash.
- Captures show the title sequence with the default advanced profile. Different
  host pacing/profile conditions mean these are functional checks, not pixel
  equivalence or performance benchmarks. Runtime shader misses still occur.
- The longer #45/#46 and Linux parity evidence remains in
  [the issue record](../TRIAEVUM_ISSUES_45_46.md). This release does not certify
  a complete playthrough or close every remaining issue qualification item.

## Known Limits

Mid-flashback savestate restore remains unreliable even though uninterrupted
Sheik revelation returns to gameplay. Prefer normal saves and back up settings.
Old Flatpak installations are not automatically migrated to AppImage storage.
The established F1 surface is retained; the F1/F12 redesign is not enabled.
Android and macOS are not included. Packaging remains marked as an audited
prerelease candidate, not a blanket stable-release readiness certification.
